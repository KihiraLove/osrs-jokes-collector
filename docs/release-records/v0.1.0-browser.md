# Final local browser acceptance

Date: 2026-11-26. Collector source:
`4495dae8e637b279eb2a16c381070f2cfeff0da7` (merged PR #21). The production UI
is unchanged from the published v0.1.0 runtime. No new image was built/published
for this verification.

The compiled application ran on a loopback-only listener with disposable
PostgreSQL, seeded pagination fixtures and generated credentials. The admin key
was passed privately to the native login form; it was not echoed into browser
test output. The preview, database and temporary credential file were removed
after the checks. No live collection or RuneScape client was used.

## Observed results

- Empty submission showed native required-field feedback and focused the joke.
  A 4,001-character draft stayed intact and reported the 4,000-character limit.
- Switching joke type preserved the draft. A single joke with quotes,
  backslash, Unicode and an internal newline submitted without a theme.
- A two-part joke submitted with an existing theme plus a newly typed theme.
  Enter added themes; removing a theme chip returned focus to the entry field;
  Space selected the theme again in the complete checkbox catalog.
- Native key-only login reached the admin listing and displayed the submitted
  text and both theme associations correctly.
- Two jokes selected under PvM stayed selected after filtering to Skilling.
  The summary reported two hidden selections. On the older page, the shared
  two-part joke was already checked. Selecting another joke produced three
  unique selections, including the hidden PvM-only joke.
- One create-and-assign action processed all three jokes and cleared selection.
  Selecting the resulting deck and moving its page moved all three to another
  deck. Unassignment preserved the jokes and cleared selection again.
- Renaming an empty deck preserved the displayed export UUID. The populated
  deletion confirmation showed its three-joke impact; Cancel preserved it.
  Permanent deletion was covered by the HTTP/Docker golden path rather than
  performed through this browser session.
- Export with no selection showed actionable feedback. Keyboard checkbox
  selection and native download-button activation worked. Attachment contents
  and schema were verified by the owner-confirmed published-image HTTP smoke
  check; browser download-event/file capture was not used.
- At 320px, public forms, admin filters/actions and export controls wrapped
  without horizontal overflow (document content/client width both 305px, plus
  the scrollbar). Desktop layouts were also visually checked.
- Space toggled a joke checkbox while retaining focus. Clear selection reset
  the count. Logout returned to key login; revisiting a protected URL showed
  “Log in to continue.” Browser JavaScript error logs were empty.

An explicit script-disabled browser session was not run: the in-app browser
does not expose that switch. Native fallback form/selection requests remain
covered by the owner-confirmed HTTP tests, including joke-type preview. Keep
the no-JavaScript item in the reusable manual checklist for future releases.

The owner also confirmed the full suite and published-image Compose check
passed after PR #21. This establishes local application/image acceptance; it
does not establish live Cloudflare/Traefik TLS, caching, forwarding or origin
isolation. Those deployment checks are explicitly deferred by the owner until
deployment. Plugin work remains separately owner-managed.
