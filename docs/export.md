# Deck JSON export

Sign in at `/admin`, then open **Export**. Check one or more decks and choose
**Download selected decks**, or choose **Download all decks** to include every
deck present at download time. The latter ignores the checkboxes. No JavaScript
is required. The browser saves a UTF-8 JSON attachment named `decks.json`.

Every chosen deck is exported in full, regardless of theme filters, pagination
or selected joke rows. Unassigned jokes are excluded. Empty decks are included
with `"jokes": []`. At least one deck must exist and be selected. Selected IDs
are case-insensitively deduplicated; if any selected deck was deleted, the entire
download fails with a conflict and a refreshed deck list. Nothing is partially
downloaded and exporting does not change deck membership or joke selection.

Downloads require an authenticated admin session and a valid same-origin CSRF
form submission. Responses use `Cache-Control: private, no-store`; proxy/CDN
configuration must preserve this policy for every `/admin` route.

## Format and ordering

The [JSON Schema](decks.schema.json) describes the exact allowed fields:

```json
{
  "decks": [
    {
      "id": "immutable-deck-id",
      "name": "OSRS",
      "jokes": ["A single joke.", "A setup.\n\nA punchline."]
    }
  ]
}
```

The only top-level property is `decks`. Each deck contains only `id`, `name` and
`jokes`. IDs are immutable UUID strings generated by the collector; renaming
preserves them. Names are the current display names. Deck IDs must be unique
within a document: the database/exporter and plugin enforce this invariant in
addition to the structural JSON Schema, which does not enforce uniqueness by
one object property. The schema allows any nonblank string ID to match the
plugin contract.

A single-part joke exports its stored text. A two-part joke joins its setup,
two actual newline characters, then its punchline. `JSON.stringify` escapes the
JSON syntax; it does not strip comments or reinterpret string content. Internal
newlines, quotes, backslashes, tabs and Unicode survive unchanged. Submission
normalization has already trimmed outer whitespace; export does not normalize
the stored text again. Themes, joke IDs, timestamps and authentication or
moderation data are never exported.

One PostgreSQL statement reads the selected decks and their jokes from a single
snapshot. Decks sort by normalized name using the database's `C` collation, then
ID. Jokes sort oldest first by their full creation timestamp (including
microseconds), then ID. Checkbox order does not change the result. Files use
two-space indentation, LF formatting and a final newline, with no timestamp or
other changing metadata, so unchanged data produces identical bytes.

## Examples and plugin verification

These fixtures are compared byte-for-byte with actual PostgreSQL-backed admin
downloads in `test/export.test.ts`:

- [One populated deck](examples/one-deck.json).
- [Multiple decks, including an empty deck](examples/decks.json).

They include both joke types, Unicode, quotes, backslashes, comment-like text,
CRLF, tabs and embedded blank lines. They can be imported unchanged into the
OSRS Jokes plugin; cross-repository verification with the actual Java importer
is tracked in [issue #9](https://github.com/KihiraLove/osrs-jokes-collector/issues/9).
